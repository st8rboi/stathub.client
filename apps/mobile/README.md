# Приложение судьи (MVP)

Мобильное приложение для судьи: подключиться к матчу, который ему назначили,
вести статус матча и видеть таймер периода. Матчи создаёт организатор в админке. Живёт в том же монорепо, что и админка организатора
(`apps/web`), на общих API-контрактах бэкенда `stathub.server`.

## Что уже работает

| Экран | Что делает | Эндпоинты |
|---|---|---|
| Вход | логин и пароль, выданные организатором | `POST /auth/login` |
| Главная | мои матчи, неотправленные события, последние матчи с устройства | `GET /referee/matches` |
| Подключение | код матча (GUID/ссылка), QR-скан, список матчей этапа | `GET /matches/{id}`, `GET /matches?stageId=` |
| Матч | статус, счёт, секундомер периода, протокол | `GET /matches/{id}/state`, `POST /matches/{id}/events` |
| Сервер | адрес WebApi, проверка связи | `GET /public/leagues` |

## Работа без сети

Всё, что делает судья на экране матча, сначала записывается на устройство и сразу видно на экране:
голы, карточки, отмены, а также начало матча, пауза, новый период и финальный свисток. Статус идёт
той же очередью, что и голы, поэтому последний гол не может потеряться из-за завершения матча.

- **Отправка** ([syncEngine](src/events/syncEngine.ts)): с любого экрана каждые 15 секунд и при возвращении
  в приложение. Фоновой отправки нет: если приложение закрыто, очередь уйдёт при следующем открытии.
- **Подготовка**: пока есть сеть, главный экран скачивает состав, дисквалификации и протокол незавершённых
  назначенных матчей ([prefetch](src/match/prefetch.ts)), и они откроются после перезапуска без связи.
- **Отказы сервера**: сервер разбирает батч по событиям. Отклонённое событие показывается судье
  с причиной и не блокирует остальные. Дисквалифицированный игрок не отказ: событие принимается
  с пометкой для организатора.
- **Сессия**: без сети не разлогинивает, токены стираются только по явному отказу сервера.
  Если сессия истекла, вести матч можно дальше, очередь уйдёт после входа.
- **Снятое назначение**: события остаются на устройстве, судья видит сообщение; после повторного
  назначения они отправятся.
- **Время**: часы устройства приводятся к серверным. Поправка считается по заголовку `Date`, а сервер
  поправляет время событий по полю `sentAtUtc` батча, поэтому поздняя отправка не сдвигает время.

Событие получает UUID на устройстве, сервер идемпотентен по нему: повторная отправка безопасна.
Отмена — отдельное событие `EventVoided`, смену статуса отменить нельзя.

## Запуск

Из корня `stathub.client`:

```bash
pnpm install
pnpm dev:mobile     # Expo dev server (QR-код / эмулятор)
```

Сервер должен быть запущен: `dotnet run --project src/Stathub.WebApi` (http-профиль, порт **5248**).
Адрес сервера задаётся в приложении на экране «Сервер» и хранится в AsyncStorage:

- Android-эмулятор — `http://10.0.2.2:5248` (значение по умолчанию);
- iOS-симулятор и web — `http://localhost:5248`;
- физический телефон — LAN-адрес компьютера, например `http://192.168.1.10:5248`
  (телефон и компьютер в одной сети).

## Проверка без Android-эмулятора

1. **Телефон + Expo Go** — самый достоверный вариант: `pnpm dev:mobile`, отсканировать QR-код
   (телефон и компьютер в одной Wi-Fi, либо запускать с `--tunnel`).

2. **Браузер на компьютере** — быстро проверить экраны и сценарий целиком:

   ```bash
   pnpm dev:mobile            # затем нажать «w» в терминале
   # или сразу
   pnpm dev:mobile -- --web
   ```

   Открывается http://localhost:8081. Это версия на `react-native-web`: работают навигация,
   формы, AsyncStorage (ляжет в localStorage) и запросы к API. Ограничения: QR-сканер
   (камера и `BarcodeDetector`) может не работать — код матча вводится вручную; жесты и
   вибрация отличаются от телефона.

   Для запросов из браузера сервер должен отдавать CORS: в `Development` политика уже включена
   (`Program.cs`), разрешены только `localhost`/`127.0.0.1`. Адрес API в браузере —
   `http://localhost:5248`, это значение по умолчанию для web.

## Структура

```
app/                 маршруты expo-router
  _layout.tsx        провайдеры: TanStack Query, настройки, safe area, стек
  index.tsx          главная
  connect.tsx        подключение по коду и этапу
  scan.tsx           QR-сканер (expo-camera)
  settings.tsx       адрес сервера и проверка связи
  stage/[stageId].tsx  матчи этапа
  match/[id].tsx     экран матча
src/api/             типы контрактов и HTTP-клиент (fetch + ProblemDetails)
src/events/          офлайн-очередь, отправка, проекция статуса и счёта
src/hooks/           запросы TanStack Query со снимками для работы без сети
src/match/           статусы, форматирование, секундомер, предзагрузка, строка матча
src/storage/         AsyncStorage: настройки, недавние матчи, снимки данных
src/ui/              кнопки, карточки, поля, бейджи, экран-контейнер
```

## Технические решения

- **expo-router** вместо ручной навигации: экраны — файлы, deep link `stathub://match/<guid>`
  уже работает и используется QR-кодом.
- **TanStack Query + снимки в AsyncStorage** ([usePersistedQuery](src/hooks/usePersistedQuery.ts)):
  ответы сервера переживают перезапуск приложения без сети.
- **AsyncStorage** и для очереди: на матч приходится несколько десятков событий.
- **Секундомер** считается из полей матча (`periodStartedAtUtc`, `pausedAtUtc`, `periodPausedMilliseconds`).
