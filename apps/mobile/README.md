# Приложение судьи (MVP)

Мобильное приложение для судьи: подключиться к матчу, который ему назначили, или создать новый,
вести статус матча и видеть таймер периода. Живёт в том же монорепо, что и админка организатора
(`apps/web`), на общих API-контрактах бэкенда `stathub.server`.

## Что уже работает

| Экран | Что делает | Эндпоинты |
|---|---|---|
| Главная | вход в подключение/создание, последние матчи с устройства | — |
| Подключение | код матча (GUID/ссылка), QR-скан, список матчей этапа | `GET /matches/{id}`, `GET /matches?stageId=` |
| Новый матч | создание матча на этапе с датой и временем | `POST /matches` |
| Матч | статус, счёт, секундомер периода, события протокола | `POST /matches/{id}/start·stop·resume·next-period·finish`, `GET /matches/{id}/state`, `POST /matches/{id}/events` |
| Сервер | адрес WebApi, проверка связи | `GET /leagues` |

Кнопки статуса показываются только для переходов, которые разрешает домен `Match`:
начать — из `Scheduled`, пауза и завершение — из `InProgress`, продолжить — из `Pause`,
следующий период — из `InProgress`/`Pause`.

## События и офлайн-очередь

Гол, автогол, жёлтая и красная карточки и отмена события (кнопки «Замена» в интерфейсе судьи нет —
серверный тип `Substitution` остаётся на будущее). Счёт на экране — проекция
протокола: считается по тем же правилам, что и на сервере (автогол засчитывается сопернику,
отменённые события не учитываются), поэтому только что отмеченный гол виден сразу.

- При голе после выбора команды приложение показывает **состав команды в этом турнире**:
  автора берём из заявок (`TournamentTeam` → `PlayerRegistration` → игроки), плюс вариант
  «Без автора». Событие хранит `playerId`, поэтому статистика игроков потом считается из логов.
- Названия команд подтягиваются из справочника: контракт матча хранит только `teamId`.
- Событие получает UUID на устройстве и сразу попадает в `AsyncStorage` (офлайн-очередь),
  а на сервер уходит батчем, когда есть связь.
- Сервер идемпотентен по этому UUID: повторная отправка после таймаута не создаёт дублей.
- Отмена — отдельное событие `EventVoided` со ссылкой на отменяемое; в протоколе оно остаётся
  зачёркнутым. Отменить уже отменённое нельзя.
- Смена статуса матча пока не в очереди: `start/stop/resume/...` требуют сети.

## Чего пока нет (ждёт бэкенд)

- **Назначение судьи на матч и вход** — модуль Identity пуст, поэтому экран «Назначенные мне»
  честно показывает заглушку, а матч открывается по коду или из списка этапа.
- **Игроки в событиях** — событие привязывается к команде; выбор игрока и ассистента появится,
  когда будет модуль заявок (`PlayerRegistration`). Поля `playerId`/`relatedPlayerId` на сервере
  и в контракте уже есть.
- **Названия команд** — модуль Teams пуст, сервер хранит только идентификаторы.
- **Офлайн для статусов** — кэш последнего матча позволяет открыть экран без связи,
  но смена статуса без сети вернёт ошибку.

## Запуск

Из корня `stathub.client`:

```bash
pnpm install
pnpm dev:mobile     # Expo dev server (QR-код / эмулятор)
```

Сервер должен быть запущен: `dotnet run --project src/Stathub.WebApi` (http-профиль, порт **5248**).
Адрес сервера задаётся в приложении на экране «Сервер» и хранится в AsyncStorage:

- Android-эмулятор — `http://10.0.2.2:5248` (значение по умолчанию);
- iOS-симулятор и web — `http://localhost:5248`;
- физический телефон — LAN-адрес компьютера, например `http://192.168.1.10:5248`
  (телефон и компьютер в одной сети).

## Проверка без Android-эмулятора

1. **Телефон + Expo Go** — самый достоверный вариант: `pnpm dev:mobile`, отсканировать QR-код
   (телефон и компьютер в одной Wi-Fi, либо запускать с `--tunnel`).

2. **Браузер на компьютере** — быстро проверить экраны и сценарий целиком:

   ```bash
   pnpm dev:mobile            # затем нажать «w» в терминале
   # или сразу
   pnpm dev:mobile -- --web
   ```

   Открывается http://localhost:8081. Это версия на `react-native-web`: работают навигация,
   формы, AsyncStorage (ляжет в localStorage) и запросы к API. Ограничения: QR-сканер
   (камера и `BarcodeDetector`) может не работать — код матча вводится вручную; жесты и
   вибрация отличаются от телефона.

   Для запросов из браузера сервер должен отдавать CORS: в `Development` политика уже включена
   (`Program.cs`), разрешены только `localhost`/`127.0.0.1`. Адрес API в браузере —
   `http://localhost:5248`, это значение по умолчанию для web.

## Структура

```
app/                 маршруты expo-router
  _layout.tsx        провайдеры: TanStack Query, настройки, safe area, стек
  index.tsx          главная
  connect.tsx        подключение по коду и этапу
  scan.tsx           QR-сканер (expo-camera)
  create.tsx         создание матча
  settings.tsx       адрес сервера и проверка связи
  stage/[stageId].tsx  матчи этапа
  match/[id].tsx     экран матча
src/api/             типы контрактов и HTTP-клиент (fetch + ProblemDetails)
src/hooks/           запросы и мутации TanStack Query
src/match/           статусы, форматирование, секундомер, строка матча
src/storage/         AsyncStorage: настройки, недавние матчи, время пауз
src/ui/              кнопки, карточки, поля, бейджи, экран-контейнер
```

## Технические решения

- **expo-router** вместо ручной навигации: экраны — файлы, deep link `stathub://match/<guid>`
  уже работает и используется QR-кодом.
- **TanStack Query**: после каждого действия инвалидируется запрос матча, поэтому статус и период
  на экране — это ответ сервера, а не локальная копия.
- **AsyncStorage** для настроек, кэша недавних матчей и накопленного времени пауз.
- **Секундомер периода** считается на клиенте: сервер отдаёт `periodStartedAtUtc` и не хранит
  время остановок, поэтому длительность пауз накапливается локально по ключу «матч + период».
  Для завершённого матча время не показывается — сервер не хранит момент финального свистка.
