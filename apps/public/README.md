# Публичная витрина (`apps/public`)

Отдельное SPA-приложение: матчи, таблицы и лиги разных организаторов в одном месте —
единая публичная витрина по [documentation/doc.md](../../../documentation/doc.md) §2.1.
Только чтение, без аутентификации; админка организатора живёт в `apps/web`.

## Экраны

| Маршрут | Что показывает | API |
|---|---|---|
| `/` | «Дашборд дня»: hero, полоса дат с количеством матчей, соревнования с раскрытием и правый сайдбар с таблицей лиги | `GET /public/matches?fromUtc=&toUtc=`, `GET /public/leagues`, `GET /public/stages/{id}` |
| `/leagues` | каталог опубликованных лиг: поиск по названию и городу | `GET /public/leagues` |
| `/leagues/:slug` | лига → турниры → этапы | `GET /public/leagues/{slug}` |
| `/stages/:stageId` | матчи этапа и полная таблица | `GET /public/stages/{id}` |
| `/matches/:matchId` | счёт, период, секундомер, протокол | `GET /public/matches/{id}` |
| `/statistics` | статистика игроков по турниру: голы, автоголы, карточки, матчи | `GET /public/tournaments/{id}/statistics` |

## Дизайн

Светлая тема с зелёным акцентом, сжатые заголовки капсом, карточки соревнований
с раскрытием, строки матчей в две строки (логотипы команд + счёт/время справа),
липкий сайдбар с таблицей. Логотипы команд и лиг загружаются в админке
(`POST /teams/{id}/logo`, `POST /leagues/{id}/logo`) и приходят в публичных DTO.

## Живые обновления

Счёт приходит по SignalR (`/hubs/matches`, группы `match:{id}` и `live`). Пуш — только
сигнал перечитать REST-состояние; независимо от него страница матча опрашивает
`GET /public/matches/{id}` раз в 15 секунд, пока матч идёт, а расписание — раз в минуту.
Поэтому разрыв WebSocket не оставляет зрителя со «замёрзшим» счётом.

## Запуск

```bash
pnpm install            # из корня stathub.client
pnpm dev:public         # http://127.0.0.1:5174
```

Нужен запущенный WebApi на `http://localhost:5248` (http-профиль): Vite проксирует
`/api` на него, а `/hubs` — с `ws: true`, поэтому CORS в dev не участвует.

Сборка: `pnpm build:public`.
